## KW-GPU-DEVICE-ERROR-SUBSTITUTE — No regression is built to make the GPU PSTD provider return an error at or after device acquisition [patch] — todo

priority: verification; needs: none; basis: fa8c4a892787ec8907ddb504ac3a7fb62bf3874c; scope: `crates/kwavers-simulation/src/dispatch/pstd/gpu.rs`, `crates/kwavers-simulation/src/solver_adapters/gpu_pstd.rs`, `crates/kwavers-simulation/src/runner.rs`

- **Origin.** Split from `KW-GPU-048`, which #1053 closes. ADR 037 says the runner "returns typed errors for unsupported inputs or acquisition failure". #1053 pins what the runner returns for two requests the provider refuses before device acquisition: zero time steps (`InvalidInput`) and two absorption exponents (`FeatureNotAvailable`). The Leto dispatch returns `Ok` for both (an empty record for zero steps). Run for #1053 as mutants of the dispatch, on a host with an adapter: a fall-back to Leto for every provider error, or for either of those two variants, failed a test, both when it returned Leto's outcome and when it kept the provider's error if Leto failed too. A fall-back taken only for `SystemError::GpuNotAvailable` or `KwaversError::GpuError` passed the 119 tests of the `gpu` build of `kwavers-simulation`, and so did one that runs Leto, drops its outcome and returns the provider's error.
- **Read at the basis.** The doc comment of `run_gpu_pstd` names `SystemError::GpuNotAvailable` (no adapter) and `KwaversError::GpuError` (an adapter that fails), and `with_auto_device` (`crates/kwavers-gpu/src/pstd_gpu/pipeline/auto_device.rs`) wraps a construction failure as `InvalidInput` ("GPU PSTD solver construction failed"). `git grep -n -i acquisition -- crates/kwavers-simulation/src` finds three doc comments, three test names and one `expect_err` message; no test makes acquisition fail. Where acquisition does fail, the device tests of `kwavers-gpu` discard the error: `make_solver` ends in `.ok()` (`crates/kwavers-gpu/src/pstd_gpu/tests/run.rs` line 45) and `test_gpu_pstd_run_produces_output` returns when it gets no solver (lines 59 to 61); not run on a host without an adapter. `run_gpu_pstd` fixes the device provider (`WgpuPstdStateProvider`); `run_gpu_pstd_with_provider` (`crates/kwavers-gpu/src/pstd_gpu/runner.rs`) takes it as a type parameter. No workflow runs the tests of the `gpu` build of `kwavers-simulation`.
- **Acceptance:** a test in which the provider returns an error at or after device acquisition for a `SolverType::PSTD` request with `FftBackend::Hephaestus`, on a request the Leto dispatch accepts, asserts that error's variant and message, runs where the gate runs, and fails when the dispatch or the adapter returns a Leto result instead.
- **Next step:** choose between a provider type parameter on the dispatch and the adapter, and a test for the adapter-less hosted runner; the second needs a workflow that runs the `gpu` build's tests (`KW-SIM-TEST-COMPILE-GRAPH`).
