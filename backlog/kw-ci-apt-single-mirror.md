## KW-CI-APT-SINGLE-MIRROR — One unreachable Ubuntu mirror fails every job that installs packages [patch] [ci] — todo

priority: verification; needs: none; basis: 95a79d4b2cf05ca2d388c5f1c9f28e7889f75d2a; scope: `.github/actions/install-system-dependencies/action.yml`; `.github/workflows/ci.yml` (`cuda-runtime-build`, step `Install container prerequisites`)

- **Finding.** The shared install action rewrites `azure.archive.ubuntu.com` to `archive.ubuntu.com` in every apt source, the mirror list `/etc/apt/apt-mirrors.txt` included, then refreshes the package index under an 8-minute `timeout` with `Acquire::Retries=3` and 20 s connection timeouts. The CUDA job's container refreshes from `archive.ubuntu.com` under the same bounds.
- **Evidence.** Pipeline run 42967312932 (push to `main` at bd7e3a1df34c88a6dba8140c198012f53519f6e5) had ten jobs fail in an install step: nine in `Install system dependencies` and `CUDA Runtime Build` in `Install container prerequisites` (the two gate jobs failed as a consequence). All ten steps ended on exit code 124 from the `timeout`, with no `Hit:` or `Get:` line for `http://archive.ubuntu.com/ubuntu`. Each of the nine runner jobs printed 11 `Ign:` lines for that host about 42 s apart, cycling over four index files (`noble`, `-updates`, `-backports`, `-security`), and no `Err:` line. The CUDA container fetched its security index from `security.ubuntu.com` and asked the archive host for three files (`jammy`, `-updates`, `-backports`): nine `Ign:` lines, then `Err: Connection failed` for two of them, and the `timeout` fired while the third was on its last attempt. The pull-request run for the same change (42965862807) passed four minutes before that run started, with the install step succeeding in the eight runner jobs that ran it (`Code Quality` and the CUDA job were skipped); the next run on `main` (42970466152) passed both steps. The cause lies outside the repository.
- **Cost.** Each of the ten jobs held a runner for 497 to 557 s before failing. The retries do not fit the bound: at about 42 s per attempt and four attempts per file, four files need about 672 s and three need about 504 s against a 480 s `timeout`, so a runner job ends before apt reports any error and the CUDA job ended during the last attempt on its third file.
- **History (from the board text of the commits).** f001507536388ad866f687e3e98a7d12c493595f added the substitution to the source files after hosted run 32234170603 timed out in `apt-get update` with `azure.archive.ubuntu.com` unavailable; 853b5f691b797008459fee3440111c397baab676 extended it to the mirror list after run 32234991542, where rewriting only the source files "left the unavailable mirror active and produced the same bounded timeout"; c8f4fcd1aef19aaa8f2422d4c3c3dd166d29a3fd moved it into the shared action. Each of the two hosts has now been the unreachable one once.
- **Hypothesis, not tested.** The mirror list holds more than one entry (the Clippy log fetches a 138-byte list, and a line holding only the `archive.ubuntu.com` address is 34 bytes), so the rewrite may turn a fallback list into one host named more than once. Whether apt moves to a later entry when the first only times out, and within what time, is not known; run 32234991542 suggests it did not do so inside the bound.
- **Outcome:** the index refresh has a second source, and an unreachable source ends in an apt error inside the step bound.
- **Acceptance:** a job log prints the mirror list the refresh uses and it names at least two hosts; with the first host made unreachable in a test job (an unroutable address substituted in the list), the refresh succeeds from the second and the log shows the time spent on the first; the retry count, connection timeout and step bound are consistent (files times attempts times the per-attempt time is below the bound, in the runner step and in the CUDA step).
- **Next step:** print `/etc/apt/apt-mirrors.txt` before and after the rewrite in one job to settle the hypothesis.
