## KW-CI-APT-SINGLE-MIRROR — One unreachable Ubuntu mirror fails every job that installs packages [patch] [ci] — todo

priority: verification; needs: none; basis: 95a79d4b2cf05ca2d388c5f1c9f28e7889f75d2a; scope: `.github/actions/install-system-dependencies/action.yml`; `.github/workflows/ci.yml` (`cuda-runtime-build`, step `Install container prerequisites`)

- **Finding.** The shared install action rewrites `azure.archive.ubuntu.com` to `archive.ubuntu.com` in every apt source, the mirror list `/etc/apt/apt-mirrors.txt` included, then refreshes the package index under an 8-minute `timeout` with `Acquire::Retries=3` and 20 s connection timeouts. The CUDA job's container refreshes from `archive.ubuntu.com` under the same bounds.
- **Evidence.** Pipeline run 42967312932 (push to `main` at bd7e3a1df34c88a6dba8140c198012f53519f6e5) had ten jobs fail in an install step: nine in `Install system dependencies` and `CUDA Runtime Build` in `Install container prerequisites` (the two gate jobs failed as a consequence). In the logs read (`Clippy (strict + ratchet)` and `CUDA Runtime Build`) apt printed one `Ign:` line for `http://archive.ubuntu.com/ubuntu` about every 42 s until the `timeout` ended the step with exit code 124. The pull-request run for the same change (42965862807) completed its install steps and passed four minutes before that run started (its CUDA job was skipped), and the next run on `main` (42970466152) passed both steps, so the cause lies outside the repository.
- **Cost.** Each of the ten jobs held a runner for 497 to 557 s before failing, and the step ended by the `timeout`, not by an apt error: four index files at about 42 s per attempt do not finish their retries inside 480 s.
- **Hypothesis, not tested.** The runner image's mirror list may name a second host after the Azure mirror; if it does, the rewrite turns a fallback list into one host named twice. The rewrite dates from f001507536388ad866f687e3e98a7d12c493595f (`fix(kwavers): Use reachable Ubuntu mirror`), whose subject implies the Azure mirror was the unreachable one then.
- **Outcome:** the index refresh has a second source, and an unreachable source fails the step within a bound derived from the retry settings.
- **Acceptance:** a job log prints the mirror list the refresh uses and it names at least two hosts; with the first host made unreachable in a test job (an unroutable address substituted in the list), the refresh succeeds from the second and the log shows the time spent on the first; the retry count, connection timeout and step bound are consistent (the retries of every index file fit inside the bound).
- **Next step:** print `/etc/apt/apt-mirrors.txt` before and after the rewrite in one job to settle the hypothesis.
