## KW-CI-CLASSIFIER-RESIDUALS — The changed-path classifier trusts a file list it does not check [patch] [ci] — todo

priority: verification; needs: none; basis: 95a79d4b2cf05ca2d388c5f1c9f28e7889f75d2a; scope: `.github/workflows/ci.yml` (the `changes` job, step `Classify the changed paths`, and `on.push.paths-ignore`)

- **Source.** Findings the judges of #1030 and #1034 filed; neither pull request changed them.
- **Unchecked list length.** The step classifies the entries of `pulls/<n>/files`. GitHub documents that endpoint as returning at most 3000 files (REST reference, "List pull requests files"), and the step does not compare the entry count with the pull request's `changed_files` field. Past the cap it sees only the first 3000 entries and can report `code=false` for a pull request that changes code. An empty list also reports `code=false`, because `code` starts `false` and only a listed path sets it.
- **Prose directories match every file type.** `backlog/*`, `docs/*` and `.githooks/*` match any file below them, and `on.push.paths-ignore` lists the same directories. `xtask/src/migration_audit.rs` reads every `.rs` file and `Cargo.toml` below the repository root, skipping any entry named `.git`, `target` or `xtask`; its two jobs run on pushes, the schedule and manual dispatch, never on pull requests. A push that adds a `.rs` file or manifest under one of those directories and touches no other path starts no run, so the two audits first see the file at the next scheduled run or the next push that touches a path outside the ignored set. At the basis no such file exists.
- **Hypothesis, not tested.** The push trigger's `paths-ignore` may evaluate only the new path of a rename. If it does, a push to `main` that renames a source file into an ignored directory starts no pipeline run. #1034 closed the same hole for pull requests only. The workflow-syntax reference adds a limit of its own: when the diff a path filter evaluates holds more than 3000 files and the matching files are not among the first 3000, the workflow does not run.
- **Cosmetic.** The step summary prints a rename's old and new paths as two unlabeled lines.
- **Outcome:** the classifier runs the gate whenever its file list is incomplete, and a `.rs` file or manifest counts as code wherever it sits, for the classifier and for the push filter.
- **Acceptance:** the step's script, extracted from the workflow and run under `bash --noprofile --norc -eo pipefail` with a stub `gh` (the method of the #1034 judge), reports `code=true` when the entry count differs from `changed_files` and when a `.rs` file or `Cargo.toml` sits under `backlog/`, `docs/` or `.githooks/`, and still reports `code=false` for a pull request changing only `backlog.md` and `.md` files under `backlog/`; the push filter no longer ignores a `.rs` file or `Cargo.toml` under the three directories, shown from the filter-pattern rules of the workflow-syntax reference and confirmed by the first such push; the rename hypothesis is settled by one observed push or by a cited GitHub document, and `paths-ignore` changes only if it holds.
- **Next step:** add the count comparison (one more `gh api` call for `changed_files`), then make `.rs` and `Cargo.toml` paths count as code ahead of the prose patterns in the `case` and narrow the push filter to match.
