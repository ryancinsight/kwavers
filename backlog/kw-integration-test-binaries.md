## KW-INTEGRATION-TEST-BINARIES — kwavers integration tests link one binary per file: 89 targets, 81 on the push gate [patch] [perf] — todo

priority: tightening; needs: none; basis: 2824e0ecf45fd62c381bf935fd032326171b1fdd; scope: `crates/kwavers/tests/`, `crates/kwavers/Cargo.toml` (`[[test]]` tables), `scripts/integration_tests.py` and its baseline

- **Finding.** `crates/kwavers/tests/` holds 89 top-level `.rs` files, each its own test target; the five subdirectories hold modules of those files and none has a `main.rs`. Eight targets are feature-gated: seven set `required-features = ["full"]` (`validation_suite`, `literature_validation`, `physics_validation_test`, `solver_test`, `dispersion_validation_test`, `elastic_wave_validation`, `physics_validation`) and `pinn_bc_validation` needs `pinn`. The push gate runs `cargo nextest run` on the gated packages with default features (`minimal`), so for `kwavers` it links the other 81.
- **Evidence (the last two push attempts for the head of #1024, the first two under the stack build profile that ryancinsight/atlas#660 landed; 600 s gate deadline, packages `kwavers-analysis` and `kwavers`).** The earlier one expired: clippy ended at 112 s and the test stage had passed 341 of 1279 tests when the deadline fired; the next attempt counted 85 test executables written by it. The later one, with those artifacts built, passed in 534 s (clippy 23 s, tests 197 s, rustdoc 103 s, verification 211 s). Earlier push attempts for #1024 under the previous profile had also expired in the test stage (three, as recorded on atlas#660).
- **Hypothesis, not shown.** Compilation is a large share of a cold test stage: at least about 290 s of the expired run's 488 s test stage, if per-test run time equals the later run's. That figure covers every unit compiled in the stage (the workspace libraries in the test profile as well as the test executables), the logs do not split compile from link time, and that run was the first under the changed profile. The other stages alone (112 + 197 + 103 + 211 = 623 s) exceed the deadline when clippy is cold, so consolidation alone is not shown to make a cold push fit.
- **Outcome:** the integration tests link as a few harness binaries (`tests/<area>/main.rs` declaring the files as modules), with every test kept.
- **Acceptance:** the test names listed by `cargo nextest list -p kwavers`, once with default features and once with `--features full` (which enables `pinn`), differ before and after only in the binary prefix (a name diff, not a count); tests behind `cfg(feature = "em_pinn_module_exists")` (a declared feature outside `full`, 21 occurrences in `electromagnetic_validation.rs`) are compared by source diff; the integration binaries listed by `cargo nextest list -p kwavers --features full --list-type binaries-only` fall from 89 to the number of harnesses; the `scripts/integration_tests.py` baseline names follow the move. Build time from `cargo build -p kwavers --tests --timings` is reported before and after with the host load and is not a pass criterion: on this host the summed test time of two gate runs of one configuration differed by a factor of 1.51 (atlas#660), so one timing comparison has no noise bound.
- **Next step:** measure first: run the `--timings` build on a cold target and read the compile and link shares; then group the files by area and move one area into a harness.
