## KW-INTEGRATION-TEST-BINARIES — kwavers integration tests link one binary per file: 89 targets, 81 on the push gate [patch] [perf] — todo

priority: tightening; needs: none; basis: 2824e0ecf45fd62c381bf935fd032326171b1fdd; scope: `crates/kwavers/tests/`, `crates/kwavers/Cargo.toml` (`[[test]]` tables), `scripts/integration_tests.py` and its baseline

- **Finding.** `crates/kwavers/tests/` holds 89 top-level `.rs` files, each its own test target; the five subdirectories hold modules of those files and none has a `main.rs`. Eight targets are feature-gated: seven set `required-features = ["full"]` (`validation_suite`, `literature_validation`, `physics_validation_test`, `solver_test`, `dispersion_validation_test`, `elastic_wave_validation`, `physics_validation`) and `pinn_bc_validation` needs `pinn`. The push gate runs `cargo nextest run -p kwavers` with default features (`minimal`), so it links the other 81.
- **Evidence (two attempts to push the head of #1024, 600 s gate deadline).** First attempt: clippy ended at 112 s and the test stage had passed 341 of 1279 tests when the deadline fired; 85 test executables carried that run's modification times. Second attempt, with those artifacts built: 534 s (clippy 23 s, tests 197 s, rustdoc 103 s, verification 211 s).
- **Hypothesis, not shown.** Building and linking these binaries is a large share of a cold test stage: at least about 290 s of the first attempt's 488 s, if per-test run time equals the second attempt's. The logs do not split compile from link time. The other stages alone (112 + 197 + 103 + 211 = 623 s) exceed the deadline when clippy is cold, so consolidation alone is not shown to make a cold push fit.
- **Outcome:** the integration tests link as a few harness binaries (`tests/<area>/main.rs` declaring the files as modules), with every test kept.
- **Acceptance:** the test names listed by `cargo nextest list -p kwavers`, once with default features and once with `--features full` (which enables `pinn`), differ before and after only in the binary prefix (a name diff, not a count); the `scripts/integration_tests.py` baseline names follow the move; `cargo build -p kwavers --tests --timings` on a cold target reports the build wall time before and after, and the after figure is lower.
- **Next step:** measure first: run the `--timings` build on a cold target and read the link share; then group the files by area and move one area into a harness.
