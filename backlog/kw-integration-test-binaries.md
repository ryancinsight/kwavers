## KW-INTEGRATION-TEST-BINARIES — kwavers integration tests link one binary per file: 89 targets, 81 on the push gate [patch] [perf] — todo

priority: tightening; needs: none; basis: 95a79d4b2cf05ca2d388c5f1c9f28e7889f75d2a; scope: `crates/kwavers/tests/`, `crates/kwavers/Cargo.toml` (`[[test]]` tables), `scripts/integration_tests.py` and its baseline

- **Finding.** `crates/kwavers/tests/` holds 89 top-level `.rs` files, each its own test target: `cargo metadata --no-deps` reports 89 targets of kind `test` for the package, beside one `lib` and one `bin`. Of the five tracked subdirectories, four hold `.rs` files that are not targets themselves and `reference/` holds only fixtures (seven `.npz` files and a JSON manifest); none has a `main.rs`. Eight targets are feature-gated: seven set `required-features = ["full"]` (`validation_suite`, `literature_validation`, `physics_validation_test`, `solver_test`, `dispersion_validation_test`, `elastic_wave_validation`, `physics_validation`) and `pinn_bc_validation` needs `pinn`. The push gate runs `cargo nextest run` on the gated packages with default features (`minimal`), so for `kwavers` it links the other 81.
- **Evidence (the last two push attempts for the head of #1024, the first two under the stack build profile that ryancinsight/atlas#660 landed; 600 s gate deadline, packages `kwavers-analysis` and `kwavers`).** The earlier one expired: clippy ended at 112 s and the test stage had passed 341 of 1279 tests when the deadline fired; the next attempt counted 85 test executables written by it. The later one, with those artifacts built, passed in 534 s (clippy 23 s, tests 197 s, rustdoc 103 s, verification 211 s). Recorded on atlas#660 only (its body and its comment 6786730352; the logs of the earlier attempts are no longer on disk): three earlier push attempts for #1024 under the previous profile also expired in the test stage; the expired run above started at 22:56:56 local and the latest modification times of its 85 executables fall in the minutes 23:03 to 23:04.
- **Hypothesis, not shown.** Compilation is a large share of a cold test stage. Two estimates agree: at least about 290 s of the expired run's 488 s test stage, if per-test run time equals the later run's; and, from the modification times, a test build that ended between 252 and 371 s into that stage. Both cover every unit compiled in the stage (the workspace libraries in the test profile as well as the test executables), the logs do not split compile from link time, and that run was the first under the changed profile. The other stages alone (112 + 197 + 103 + 211 = 623 s) exceed the deadline when clippy is cold, so consolidation alone is not shown to make a cold push fit.
- **Outcome:** the integration tests link as a few harness binaries (`tests/<area>/main.rs` declaring the files as modules), with every test kept.
- **Acceptance:** nextest names a test `kwavers::<target> <module path>::<test>`, so a test `t` of `tests/x.rs` moves from `kwavers::x t` to `kwavers::<area> x::t`; under that mapping the names listed by `cargo nextest list -p kwavers`, once with default features and once with `--features full` (which enables `pinn`), are the same set before and after (a name diff, not a count); the tests behind `#[cfg(all(feature = "pinn", feature = "em_pinn_module_exists"))]` (21 sites in `electromagnetic_validation.rs`; `em_pinn_module_exists` is a declared feature outside `full`) are compared by source diff; `cargo metadata --no-deps` reports one target of kind `test` per harness directory in place of 89; the `scripts/integration_tests.py` baseline names follow the move. Build time from `cargo build -p kwavers --tests --timings` is reported before and after with the host load and is not a pass criterion: one timing comparison on this host has no noise bound (atlas#660 records two gate runs of one configuration whose run time, summed over the 152 tests both logs hold, differed by a factor of 1.51; that is test run time, cited for the scale of host noise only).
- **Next step:** measure first: run the `--timings` build on a cold target and read the compile and link shares; then group the files by area and move one area into a harness.
